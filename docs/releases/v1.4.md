# Agent Handoff 1.4

Agent Handoff 1.4 keeps security and evidence work proportional to concrete risk so a working vertical slice is not delayed by unsupported hardening.

## Highlights

- Blocking security work must be tied to a concrete and credible current-scope threat or failure scenario.
- The justification identifies the affected asset or trust boundary, applicability, likely impact, minimum sufficient control, and verification.
- Unsupported proposals are classified as non-blocking hardening, follow-up work, explicitly owner-accepted risk, or out of scope.
- MVPs, prototypes, and runtime spikes preserve the existing security baseline, address concrete critical risks, and run the smallest useful end-to-end scenario early.
- Optional hardening, exhaustive compatibility checks, and defense in depth normally follow a working vertical slice.
- A warning or documentation may be sufficient for local, owner-only, and easily recoverable risks.
- Stronger safeguards remain expected for secrets, untrusted input, external network access, privilege boundaries, destructive actions, sensitive data, supply-chain exposure, and verified legal or project requirements.
- Existing security controls cannot be weakened without an explicit owner decision.
- A 10–15% security-and-evidence share is only a non-binding planning heuristic.
- Reviews, reports, and handoffs distinguish blocking risk, follow-up hardening, and owner-accepted risk.

## What this does not require

Standard 1.4 does not require a threat model for every Pull Request, automated risk scoring, a fixed security-work percentage, new approval stages, or a separate Issue for every non-blocking hardening idea.

The checker verifies the presence of one proportionality checklist item. It does not determine whether a threat is realistic or whether a control is sufficient.

## Compatibility

Standard 1.4 preserves the containerization decision gate, stable GUI testing rules, task reporting, work claims, and the existing security baseline from Standard 1.3.

Projects can adopt the proportionality rule without changing application architecture or removing existing controls.
